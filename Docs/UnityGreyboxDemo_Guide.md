## 直接运行

1. 用 Unity 6000.3.28f1 打开本工程，保存当前尚未保存的场景，等待脚本与新资产导入完成。
2. 打开 `Assets/_Game/Scenes/Level_2_1.unity`，按 Play，点击 Game 视图获得键盘焦点。
3. A/D 或左右箭头移动，Space 跳跃，S/下箭头在空中向下冲跃，R 重置当前关。地面按下冲不会传送。
4. 2.1 接触终点后短黑屏自动进入独立的 2.2 场景；2.2 完成后显示提示，R 可重新开始 2.2。
5. 默认窗口 1920×1080、允许缩放。Game 视图可选 16:9；其他比例会留黑边。地图 24×12，正交视野约 27.02×15.2，一屏覆盖关卡及调试栏，不需要跟随镜头。

场景、关卡数据、Player/Box 预制体及纯色资源已经生成，无需逐个放置或挂载脚本。原 SampleScene 和现有 Universal 2D 设置保留。

若需要重新生成，运行 `Tools > YiChiLanRan > 0 Generate complete greybox demo`。这会重建本工具生成的三个场景、三份数据和两个预制体；先保存这些生成文件上的个人修改。菜单 1、2、3 可单独生成沙盒或某关；菜单 4 重新配置窗口、120Hz 步长和构建场景列表。已打开的用户场景不会被工具自动保存或替换；编辑器中有未保存的无名场景时请先保存再生成。

## 解法提示

### 2.1

- 把蓝箱①推到第一高台左边，跳上箱，再向右跳上高台。
- 在黄色标记内跳起并下冲，人物变白，整图镜像，三箱保色。
- 把白箱②推到右侧白色台阶，借箱登上中层路线。
- 向右下到箱③左侧，推③使整个箱体进入绿色标记；跳上箱顶，再跳起下冲。
- 人物和③变蓝，其他箱保色。把③推到终点台左侧，再借箱跳上旗帜。

### 2.2

- 从左下沿底层到黄色，跳起下冲。
- 白态向左到绿色①，先单人下冲，变回蓝态。
- 从绿色①右侧起跳到左上平台，越过①到其左边，把①推下平台右沿，使其落进绿色①。
- 跳上①，再跳起下冲；人物与①变白。②自动落入中部坑，顶面与道路齐平。
- 从①左边落地，把①推过填坑处，到右侧白色高台边；借①登台。
- 下到③左侧地面，推③整个进入绿色②，再从箱顶上方下冲。
- 人物和③变蓝，①②保持白；把③推到终点台边，借箱登旗。

颜色、世界镜像状态、传送次数、最近传送入口及失败原因显示在左上角。标号随箱子移动；标记和文字保持正立。

## 参数与实现选择

- 人物碰撞框 0.56×0.76，箱子视觉/主碰撞框 1×1，箱高/人高约 1.316。
- 横移 5.2，重力 36，普通跳 9.2，蓝材质跳 11.5，蓝回弹 13.98，下冲 21，普通下落上限 12.4；固定物理步长 1/120s。这是 Unity 校准值，不是 Phaser 像素值直接赋值。
- 理论普通跳高 1.176，蓝跳高 1.837，蓝回弹高 2.714；核心蓝台阶高 2.78，需要箱子。实际离散物理轨迹另见 CSV，不把理论值当实测值。
- 2.2 坑宽 1.08、箱宽 1.00；留少量接触间隙，避免②被坑口托住。人物与推行箱仅对不超过 0.04 的细小接触缝隙执行安全抬升，不能跨越谜题台阶。
- 所有地形和所有箱子严格按中心 y'=12-y 镜像；只有人物保留安全落位。参与箱仅改变颜色，不能再吸附到目标支撑面。传送前检查所有动态对象的目标空间，不安全则整次拒绝。
- 各箱使用自身颜色处理碰撞和重力，异色箱不会被人物推动。限箱障碍按对象类型过滤。
- 承重白色地形配置为稳固；代码支持显式可碎地形，当前谜题没有未经策划标注的可碎区域。蓝地形与蓝箱保留材质高跳/回弹，白箱不会回弹或碎裂。
- 对象间通过统一 PhaseCollisionSystem 配置 Collider2D 对过滤；没有改动用户已有全局 Layer Collision Matrix 或输入动作资产。

## 已执行的自动检查

在独立项目副本中使用 Unity 6000.3.28f1 执行，避免与当前编辑器实例争用或模拟用户打开的场景。

- Unity 实际编译运行时及 Editor 程序集通过；本地编译辅助脚本也分别检查两个程序集。
- 通用沙盒：真实 Rigidbody2D 落地、蓝跳、普通跳不传送、黄色传送、绿色带箱、非参与箱保色、单次触发、安全失败不修改世界状态。
- 两关完整路线：从出生点出发，仅给移动、跳跃和 Dive 指令，由 Unity PhysicsScene2D.Simulate 连续推进，无中途改坐标；每个采样步检查实体穿透。
- 2.1 实际事件：Yellow solo → Green + Box 3；2.2 实际事件：Yellow solo → Green 1 solo → Green 1 + Box 1 → Green 2 + Box 3。均抵达旗帜且最终颜色符合规格。
- 2.2 在第三次传送后检查②实际填坑位置，随后实际推动①通过；限箱障碍通过真实推箱和人物穿越检查；黄色后的右侧白色台阶通过重复跳跃/下冲尝试检查。
- 两关完成后、模拟传送锁定状态下的重置检查通过。
- 1920×1080、1600×900、1280×720、1366×768、800×600 的视口比例及完整地图覆盖计算通过。
- 真实 Play Mode 冒烟：生产 Start/FixedUpdate 启动与落地、地面下冲拒绝、2.1 终点过渡加载 2.2、2.2 完成状态、生产重置路径均通过。此项用终点接触夹具触发切关；标准解由上述独立连续物理路线验证。

结果文件在 `DevReports/AutomatedChecks.txt`、`Route-2.1.txt`、`Route-2.2.txt`、`Regression.txt`、`PlayModeSmoke.txt`；CSV 保存轨迹。最终日志为 `DevReports/Final-Unity.log`。早期失败测试已用于修复坑口间隙、平齐接触缝隙及③左侧落脚余量；以最终报告为准。

重跑：在工程根目录 PowerShell 中运行 `./Tools/Run-UnityChecks.ps1`。默认创建独立副本、生成并测试，最后复制报告回来；不会覆盖当前场景。可加 `-PublishGenerated` 同步新生成场景/数据/预制体，再在 Unity 运行菜单 4 配置。测试工具会保留副本以便排查，不自动删除项目文件。首次副本导入可能较慢，需 Unity 正常许可证与包依赖。

`./Tools/Check-Compile.ps1 -IncludeEditor` 是快速 C# 检查。Unity 菜单 5 只在当前编辑器做规则检查；为保护用户场景，它不会在非批处理实例模拟全局物理。当前采用自定义批处理测试入口，没有注册到 NUnit Test Runner。
